## Findings

### FC-2026-033 — Low — FIXED in v1.21.2

**The gated bundle exposed origin-server identity (DigitalOcean IPs, Laravel-Forge scan paths, internal hostnames) that isn't discoverable from the public frontends — a defense-in-depth weakness.**

*Threat.* The per-card "Technical details", the `sites-list.xlsx` roster, the master/per-site `audit.xlsx`, the per-site report meta-grids, the `audit-fleet.ndjson` header, and `audit-fleet-context.md` all surfaced:

- **`serverIp`** — e.g. `203.0.113.10` (hosts 7 ICJIA strapi backends), `203.0.113.11` (3), `203.0.113.12`. These are the **origin** servers. The public frontends resolve to **Netlify** (`dvfr.illinois.gov → dvfr.netlify.app → 98.84.x`), so the origin IPs are **not** in public DNS. Exposing them invites direct origin attacks that bypass Netlify's edge (port-scan, direct Strapi exploitation, origin DDoS), and the shared-IP grouping is a server-consolidation map (one box compromise → many sites).
- **`scannedPath`** — e.g. `/home/forge/dvfr.icjia-api.cloud/strapi_v4/public/uploads`. Leaks the provisioning tool (Laravel Forge), the non-public `*.icjia-api.cloud` Strapi backend hostnames, the Strapi major version, and the on-disk layout — a precise stack + topology fingerprint.
- **`hostname`** — for strapi sites the scan records the IP again (redundant); for git sites the GitHub repo path.

Blast radius is bounded by the existing **Netlify Pro Site Password** (the whole bundle returns HTTP 401 to anyone without the password) and `noindex`, so this is **not** an open exposure — the audience is authenticated ICJIA staff. But the data sat in a deployed, downloadable artefact, so a shared/leaked password or a future gate misconfiguration would hand an attacker an origin map for free. This finding upgrades FC-2026-027 (1.7.x: "deploy bundle exposes server filesystem paths — *mitigated by Site Password*") from *mitigated* to *removed at source*.

*Fix in v1.21.2.* `serverIp`, `scannedPath`, and `hostname` are stripped from every output surface: the card tech-details now show only Website + public URL + a hostname row *only when it differs from the IP*; the columns are dropped from `sites-list.xlsx` and the `audit.xlsx` layout; the per-site report meta-grid + table cells render them blank; the NDJSON header `sources[]` are stripped at construction; `audit-fleet-context.md` drops the host. **Verified after rebuild: 0 origin-IP and 0 `/home/forge` hits** across `index.html`, `sites.html`, `accessibility.html`, the per-site reports, and `audit-fleet-context.md`.

*Tracked residual (FC-2026-035, open).* The per-file **`absolutePath`** column still carries the Forge path for strapi files in the master/per-site `audit.xlsx` ("Full file path on server" column) and in `audit-fleet.ndjson` (~8,800 entries). It can't be blanket-dropped because for **git** sites `absolutePath` is the functional GitHub blob URL; removing it cleanly needs a git-vs-strapi-aware transform. Deferred to a focused follow-up; still behind the Site Password in the meantime.

### FC-2026-034 — Moderate — FIXED in v1.21.4

**The deployed bundle shipped no `Content-Security-Policy` header.**

*Threat.* The bundle set `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, and `Referrer-Policy: no-referrer`, but **no CSP**. The bundle is built from semi-trusted inputs — site/tool metadata from `sites.json`, plus **fetched `og:title`/`og:description` strings from each live site** (v1.21.0). All of it flows through `he()` / `safeUrl()`, and the audit confirmed those paths are clean — but with no CSP, a single missed escape (or a future template edit) could load an external script or exfiltrate over `connect-src` with nothing to contain it. Defense-in-depth was absent at the transport layer.

*Fix in v1.21.4.* A strict CSP is emitted in both `_headers` (the file Netlify honours on a no-build manual deploy) and `netlify.toml`:

```
Content-Security-Policy: default-src 'self'; base-uri 'self'; form-action 'self';
  object-src 'none'; frame-ancestors 'none'; script-src 'self' 'unsafe-inline';
  style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self';
  connect-src 'self'; upgrade-insecure-requests
```

`'unsafe-inline'` is required for `script`/`style` because the bundle inlines its CSS and a small clipboard/sort/modal script (a no-build static bundle has no nonce pipeline). The audit verified the pages load **only** `self` assets + a `data:` favicon: OG card images are local (`assets/og/`), there are no external stylesheets or scripts, and the client scripts make no network calls (`connect-src 'self'`). The external links in the file tables are `<a href>` *navigations*, which CSP does not block. Net effect: external script injection, framing, plugin/object embedding, base-tag hijack, and outbound exfiltration are all blocked; the page renders unchanged. `frame-ancestors 'none'` also subsumes `X-Frame-Options: DENY` for modern browsers.

### Note — live/down status dot (v1.21.2–v1.21.3) — accepted

The `/sites` + landing-page cards now show a build-time reachability dot per site. It reveals only whether a **public** site answered an HTTP request at rollup time — no internal detail — so the information sensitivity is nil. It is computed for free from the existing OG fetch (no extra request) and immediately proved useful by flagging a registered site whose configured `siteUrl` was a dead domain (NXDOMAIN). Accepted.
